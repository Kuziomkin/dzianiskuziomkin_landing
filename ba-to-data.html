① Start here — your core strength

Data Requirements

This is your home territory — but the artifacts have different shapes in data projects than in process or requirements work. It's about translating business intent into technical specs.

  • Source Mappings — document exactly where each field in the target system comes from: source table, transformation logic, business rules. Often the most critical BA deliverable in a data project.
  • Data Flow Diagrams — show how data moves between systems, pipelines, and storage layers. Give developers and architects a shared picture of the data landscape.
  • Data Catalog & Dictionary — a searchable inventory of all data assets. Defines what each field means in business terms: business definition, valid values, and data ownership.
  • Data Lineage — documents where a piece of data was born, how it was transformed, and where it ends up. Critical for debugging data quality issues and for regulatory compliance.
  • Conceptual Data Models — defines business entities and relationships (ERDs). As a BA, you'll own this layer, ensuring the technical design matches the reality of the business.
  • Data Acceptance Criteria — in data projects, these directly become data quality rules and dbt test conditions. Documenting what "valid" means is the most concrete bridge to engineering.
② Learn this first

SQL & Analytics

You don't need to become a data engineer. But you do need to be able to query data yourself and tell a story with the results — otherwise you're dependent on others to answer every question.

  • SQL Fundamentals & Window Functions — SELECT, JOINS, and CTEs. Window functions let you calculate rankings and moving averages. This is the bedrock of analytical work.
  • KPI Storytelling — calculating the number is only 50% of the job. The other 50% is explaining it. BAs excel here by documenting the logic behind KPIs and translating charts into actionable insights.
  • Power BI / Tableau — knowing how to build a basic dashboard and read the underlying data model is essential for communicating with stakeholders.
  • Python (Pandas + Jupyter) — specifically for data manipulation and reshaping. Being able to load a dataframe and inspect it puts you in a much stronger position when working alongside engineers.
  • Statistical Thinking — SQL tells you what the data says; statistics tells you what it means. Understanding distributions and significance prevents you from reporting noise as insight.
③ Set up your sandbox — don't leave this until last

Data Platforms

You need a platform to practice SQL and build your portfolio. Don't wait — open a free account on the same week you start learning. The choice matters less than getting one running early.

  • Snowflake / Databricks — cloud-native platforms that are the easiest starting point for analysts. Most have free trials with sample datasets built in.
  • MS Synapse / BigQuery — common in enterprise ecosystems (Azure/GCP). Understanding where the data "lives" is the first step to querying it.
  • Environment Strategy — understanding the flow from Dev to Prod. BAs often manage UAT (User Acceptance Testing) in specific environments, so knowing how they differ is crucial.
  • Git basics — learn commit, branch, and pull request. It takes a weekend but pays back immediately when you start collaborating with technical teams.
④ Foundational

Data Formats & Storage

Before you can work with data, you need to understand what shape it comes in and where it lives.

  • Structured vs. Semi-structured — moving beyond CSVs to JSON and Parquet. JSON is what APIs return; Parquet is what modern warehouses use for speed.
  • Databases (OLTP / OLAP) — OLTP handles live operational data; OLAP is optimized for historical analytics. Understanding this helps you ask the right questions about data sources.
  • Lakehouses (Delta, Iceberg) — the modern standard: combining the flexibility of a data lake with the structure of a warehouse.
  • Object Storage (S3, Blob) — where raw files live before they're processed. Data almost always passes through here at some point in its lifecycle.
⑤ Design skills

Analytical Data Modeling

This is where your BA background gives you the most leverage. Analytical modeling is about structuring data so it's easy for business users to understand and fast for tools to query.

  • Star Schema & Dimensional Modeling — the formal methodology (Ralph Kimball). Fact tables surrounded by dimensions. Simple, fast, and easy for business users to query.
  • Normalized vs Denormalized — knowing when to keep data separate (efficiency) and when to flatten it (speed). A foundational design choice for every warehouse.
  • SCD Types (1 / 2 / 3) — Slowly Changing Dimensions. Crucial for answering "as of" questions, like "What was this customer's address at the time they made this purchase?"
  • Data Vault — an alternative approach for auditability and scalability. Common in large, regulated industries like banking.
⑥ Pipeline thinking

ETL & ELT

This is about how data moves from source systems into your warehouse — and how you ensure it stays accurate during the journey.

  • ETL vs ELT — the shift from transforming data *before* loading to transforming it *inside* the warehouse using SQL (ELT).
  • dbt (data build tool) — the standard for SQL transformations. You'll reference its models when documenting lineage and business logic.
  • Data Quality & Testing — using automated tests (not_null, unique) to ensure pipelines don't produce bad data. Your acceptance criteria become the test cases here.
  • Airbyte / Fivetran / Airflow — the tools that move and schedule data. They handle the "plumbing" so the team can focus on the analysis.
⑦ Strategic Foundation

Data Governance & MDM

This is where you bridge the gap between business rules and technical implementation, ensuring data is trusted, consistent, and compliant across the organization.

  • Master Data Management (MDM) — defining the "Golden Record" for core entities like Customers or Products. Solving the problem of having three different names for the same client.
  • Reference Data Management — standardizing lookup codes (e.g., country codes, status flags) to ensure every system speaks the same language.
  • Data Quality Framework — defining the 6 dimensions of quality (Accuracy, Completeness, Consistency, etc.) and the rules needed to enforce them.
  • Data Privacy & Ethics — identifying sensitive PII (Personally Identifiable Information) and ensuring compliance with GDPR/CCPA.
  • Data Stewardship — acting as the custodian of data definitions, mediating between business owners who "own" the data and engineers who "build" the systems.
  • Metadata Management — maintaining the "data about data," ensuring that every column in the warehouse has a clear, documented purpose and origin.
